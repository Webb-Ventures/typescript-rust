# 0001: AST data model

Status: Proposed (drafted for M1; awaiting review)
Owners: `ts_r_ast` (data model), `ts_r_parser` (producer); consumers: transform, codegen,
binder, checker, linter, LSP

## Goals

1. **Index-based.** Nodes live in flat arrays and refer to each other by `u32` ids. No `Box`,
   `Rc` or references between nodes. A whole file's tree is a handful of `Vec`s that are freed
   in one step.
2. **Compact.** One node is 24 bytes of payload plus an 8-byte span stored in a parallel array.
   Variable-length data (lists) live in one shared array.
3. **Plain data.** Every array element is plain-old-data made of integers, so the arrays can later
   be written to disk with rkyv (or a hand-rolled format) and read back without copying. No
   pointers, no `String`s inside nodes, no `HashMap`s whose layout depends on a hasher seed.
4. **Trivia-free.** Whitespace and comments are not nodes. Comments are kept in a side table
   sorted by position so codegen, the linter and `// @ts-r-unsafe` can find them by span.
5. **Easy to traverse and print.** One Rust `enum` with struct-like variants: consumers
   `match` on it. A generated child walker visits children in source order.

## Core ids

| Type | Repr | Meaning |
|---|---|---|
| `NodeId` | `NonZeroU32` | Index into `Ast::nodes` / `Ast::spans`. Slot 0 is a reserved dummy so `Option<NodeId>` is 4 bytes. |
| `NodeList` | `u32` | Index into `Ast::list_ranges`; each range is `{start, len}` into `Ast::list_items`. `NodeList::EMPTY` (0) is the empty list. |
| `Atom` | `u32` | Interned string in the per-file `Interner`. `Atom::EMPTY` (0) is `""`. |
| `Span` | `{start: u32, end: u32}` | UTF-8 byte offsets into the source text, half-open. |

Lists are immutable once written. The parser builds a list on a scratch stack and copies the
finished slice into `list_items` in one go, so lists never reallocate per element.

## Arrays owned by `Ast`

```text
Ast {
    nodes:       Vec<Node>        // 24 bytes each, Node::Dummy at index 0
    spans:       Vec<Span>        // parallel to nodes
    list_items:  Vec<NodeId>
    list_ranges: Vec<ListRange>   // ListRange { start: u32, len: u32 }; [0] = empty
    atoms:       Interner         // one byte buffer + (start, len) table + open-addressed index
    comments:    Vec<Comment>     // sorted by span.start
    modifier_tokens: Vec<ModifierToken> // { span, flag }, sorted by span.start
    synthetic_comments: Vec<SyntheticComment> // { node, text: Atom, trailing }, sorted by
                                  // node; added by transforms (`0 /* E.A */`), never by the parser
    root:        NodeId           // the Program node
    source_kind: SourceKind       // Ts | Tsx | Dts | Js | Jsx
}
```

All of these are flat arrays of fixed-size integer records (the interner's hash index is a
`Vec<u32>` of slots and can be rebuilt on load). Nothing in them depends on memory addresses,
so an `Ast` can be archived as-is.

## Nodes

`Node` is a `#[repr(Rust)]` enum whose variants have named fields. Every field is one of:

- `NodeId`, `Option<NodeId>`, `NodeList`: children.
- `Atom`: identifier names, cooked string values, raw bigint text, regex parts.
- Small `Copy` enums and bitflags (`BinaryOp`, `VarKind`, `Modifiers`, ...): one or two bytes.
- `bool`.

A unit test asserts `size_of::<Node>() == 24`. If a new kind would need more than five 4-byte
fields, split it with a helper node (see `HeritageClause`) instead of growing every node.

Kinds are declared once in a macro (`define_nodes!` in `ts_r_ast/src/node.rs`). The macro
generates:

- `enum Node` and a fieldless `enum NodeKind` (`node.kind()`),
- `Node::for_each_child`, which visits `NodeId` / `Option<NodeId>` / `NodeList` fields in
  declaration order. **Fields are declared in source order**, so the walk is in source order.
- `Node::map_children(ast, f)`, the same node with every child id replaced by `f(ast, id)`
  in the same order (changed lists are copied into new lists), for transforms that clone or
  rebuild subtrees.
- the debug dumper used by snapshot tests (`ast.dump()`).

The source of truth for the list of kinds and their fields is that macro. The groups are:

- **Program and statements**: `Program`, `Directive`, `Block`, `Empty`, `ExprStmt`, `If`,
  `For`, `ForIn`, `ForOf`, `While`, `DoWhile`, `Return`, `Break`, `Continue`, `Throw`,
  `Labeled`, `Switch`, `SwitchCase`, `Try`, `CatchClause`, `Debugger`, `With`,
  `VarDecl`, `VarDeclarator`.
- **Declarations**: `FunctionDecl`, `ClassDecl`, `Interface`, `TypeAlias`, `Enum`, `EnumMember`,
  `Module` (namespace / module / `declare global`), `ModuleBlock`.
- **Modules**: `ImportDecl`, `ImportDefaultSpecifier`, `ImportNamespaceSpecifier`,
  `ImportSpecifier`, `ImportAttributes`, `ImportAttribute`, `ImportEquals`, `ExternalModuleRef`,
  `ExportNamed`, `ExportSpecifier`, `ExportAll`, `ExportDefaultExpr`, `ExportAssignment`,
  `NamespaceExport` (`export as namespace X`).
- **Functions and classes**: `Param`, `Decorator`, `HeritageClause`, `ExprWithTypeArgs`,
  `PropertyDef`, `MethodDef`, `StaticBlock`, `IndexSignature`, `ComputedKey`.
- **Expressions**: `Ident`, `PrivateName`, `This`, `Super`, literals (`NullLit`, `BoolLit`,
  `NumberLit`, `BigIntLit`, `StringLit`, `RegexLit`, `TemplateLit`, `TemplateElement`),
  `TaggedTemplate`, `ArrayLit`, `Hole`, `ObjectLit`, `Property`, `ShorthandProp`, `Spread`,
  `FunctionExpr`, `ClassExpr`, `Arrow`, `Paren`, `Seq`, `Unary`, `Update`, `Await`, `Yield`,
  `Binary`, `Assign`, `Conditional`, `Call`, `New`, `Member`, `Index`, `MetaProperty`,
  `ImportCall`, TS-only `As`, `Satisfies`, `TypeAssertion`, `NonNull`, `Instantiation`.
- **Patterns** (only in binding positions: params, `var`/`let`/`const`, catch): `ObjectPattern`,
  `BindingProperty`, `ArrayPattern`, `AssignPattern`, `Rest`. Assignment targets such as
  `[a, b] = x` stay expressions (`ArrayLit`, `ObjectLit`, `ShorthandProp` with an initializer),
  as in tsc; consumers that need patterns treat the left side of `=` as a target.
- **Types**: `KeywordType`, `TypeRef`, `QualifiedName`, `ThisType`, `LiteralType`,
  `TemplateLitType`, `TemplateLitTypeSpan`, `ArrayType`, `TupleType`, `NamedTupleMember`,
  `OptionalType`, `RestType`, `UnionType`, `IntersectionType`, `FunctionType`,
  `ConstructorType`, `TypeLiteral`, `PropertySignature`, `MethodSignature`, `CallSignature`,
  `ConstructSignature`, `TypeQuery`, `TypeOperator`, `IndexedAccessType`, `ConditionalType`,
  `InferType`, `MappedType`, `ParenType`, `TypePredicate`, `ImportType`, `TypeParams`,
  `TypeParam`, `TypeArgs`.
- **JSX**: `JsxElement`, `JsxOpening`, `JsxClosing`, `JsxFragment`, `JsxAttr`,
  `JsxSpreadAttr`, `JsxExprContainer`, `JsxSpreadChild`, `JsxText`, `JsxNamespacedName`,
  `JsxMemberExpr`.
- **Recovery**: `Missing` (zero-width, stands in for an expected node that is absent). A tree
  always exists; diagnostics travel separately.

### Representation choices

- **Modifiers** (`export`, `default`, `declare`, `abstract`, `public`, `private`, `protected`,
  `readonly`, `static`, `override`, `accessor`, `const`, `in`, `out`, `async`) are a `u16`
  bitflag field (`Modifiers`) on the nodes that can carry them, as in tsc. `export function f`
  is a `FunctionDecl` with `Modifiers::EXPORT`, not a wrapper node. Decorators are a `NodeList`
  of `Decorator` nodes on classes, members and parameters.
  - As in tsc 7, a modifier keyword is parsed as a modifier wherever one can start, also
    where none is allowed (`namespace N { public class A {} }`, `function f(static x)`,
    `{ static m() {} }`, `class C { const x = 1 }`). The parser reports no error; the
    checker's grammar pass does (TS1044, TS1090, TS1042, ...). So object-literal
    `Property`/`ShorthandProp`/`MethodDef` and `MethodSignature` carry `modifiers` too.
  - Each keyword taken as a modifier is also recorded, with its span, in the side table
    `Ast::modifier_tokens` (sorted, rolled back with speculation), so grammar errors can
    point at the keyword and see repeats and order: `modifiers_in(span)` and
    `modifier_tokens_of(node)` (the tokens between a node's decorators and its first other
    child). `export`/`default` are recorded only when they modify a declaration (not for
    `export {}`, `export =`, `export default expr`). `async` on methods, function
    expressions and arrows is recorded too, although the node keeps it in `FnFlags`.
- **Type annotations** are `Option<NodeId>` fields pointing straight at a type node. The `:`
  is not stored. Type stripping is "print the node without its type fields", never text
  surgery.
- **Optional chaining** is a per-link `optional: bool` on `Member`, `Index` and `Call` (the link
  that has `?.`), like tsc. A chain is the maximal run of `Member`/`Index`/`Call`/`NonNull`
  links not interrupted by `Paren`.
- **Generic arguments/parameters** are `TypeArgs` / `TypeParams` nodes so their `<...>` span is
  known.
- **Computed keys** are a `ComputedKey { expr }` node, so a key is always one node.
- **Methods** are `MethodDef { key, value: FunctionExpr }`; getters/setters/constructors use
  `MethodKind`. Object literal methods use the same node.
- **Numbers** keep their `f64` value as two `u32` halves (to keep 4-byte alignment); the raw
  text is the span. Strings keep the cooked value as an `Atom`; the raw text is the span.
- **Template elements** keep the cooked value as an `Atom` plus `invalid_escape: bool` (tagged
  templates may contain invalid escapes); raw text comes from the span.
- **JSX text** is kept raw (`JsxText { value }` is the raw text as written); entity decoding and
  whitespace folding belong to the JSX transform.

## Comments

`Comment { span, kind: Line | Block | Hashbang, newline_before: bool }`, collected by the lexer
in source order. `Ast` provides:

- `comments_in(span) -> &[Comment]` (binary search),
- `leading_comments(pos)`: comments between the previous token end and `pos`,
  approximated as comments that end at or before `pos` after the previous node;
- `comment_text(&Comment, src)`.

Consumers that need exact attachment (codegen) walk nodes in source order and emit every
comment whose start is before the node they are about to print.

## Traversal

- `node.for_each_child(&ast, |child| ...)`: direct children in source order.
- `ast.children(id) -> SmallVec`-like iterator wrapper for convenience.
- `ts_r_ast::visit::walk(&ast, root, &mut impl Visitor)`: depth-first pre/post order with
  `Visitor::enter(&mut self, ast, id) -> Walk` (`Continue` / `SkipChildren` / `Stop`) and
  `Visitor::leave(&mut self, ast, id)`. The walk uses an explicit stack, so deep trees do not
  overflow the native stack.
- `ParentMap::build(&ast)`: one `Vec<Option<NodeId>>` filled by a single walk. Parents are not
  stored by the parser, so the hot path stays one write per node; tools that need parents
  (linter, LSP, checker) build the map once per file (4 bytes per node).

## Interning

Each file has its own `Interner`. Atoms are only meaningful together with their file's `Ast`.
Cross-file interning (the checker's global symbol table) maps file atoms to global ids at bind
time. The interner is append-only; the parser's speculative rollback does not remove atoms
(harmless: an unused string).

## Serialization (later)

Not implemented in M1. Requirements kept now so it stays possible:

- every array element type is `Copy`, has no padding-sensitive invariants and no pointers;
- enums are fieldless or carry only such fields;
- `NodeId` 0 is reserved and never referenced, so a zeroed file is detectably invalid;
- format version = hash of the `define_nodes!` input, bumped automatically when kinds change.

## Invariants

1. Every `NodeId` stored in a node is `< nodes.len()`, never 0, and its node was allocated
   before the referencing node (children before parents). The root is the last node.
2. `spans[i]` covers all of node `i`'s children; spans are within the source length.
   Exception: a `Missing` node is zero-width at the end of the previous token, so it can sit
   just before its parent's start (separated only by trivia). Other nodes that consumed no
   tokens during error recovery are zero-width at the same place.
3. Child walk order equals source order.
4. Parsing never panics; on errors the tree still satisfies 1–3, using `Missing` nodes.
