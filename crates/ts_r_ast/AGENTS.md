# ts_r_ast

The arena AST for TypeScript, TSX, JavaScript and `.d.ts`, produced by `ts_r_parser` and
consumed by transform, codegen, binder, checker and lint. The design record is
[../../docs/design/0001-ast.md](../../docs/design/0001-ast.md); read it before adding node kinds. Root
rules: [../../AGENTS.md](../../AGENTS.md).

## API in one breath

`Ast` owns everything: `nodes: Vec<Node>`, parallel `spans`, `list_items`/`list_ranges` for
child lists, an `Interner` for identifier and string values, `comments`, `root` and
`source_kind`.

- `ast.node(id)` returns a `&Node`, `ast.span(id)` its byte span, `ast.kind(id)` the
  `NodeKind`.
- `ast.list(list)` returns `&[NodeId]`; `ast.atom(a)` returns `&str`.
- `Node` is one enum with struct-like variants, generated by `define_nodes!` in `node.rs`
  (about 150 kinds, 24 bytes each). The macro also generates `NodeKind`, `for_each_child`
  (source order), `map_children` and `dump_fields`.
- `ast.map_children(id, &mut |ast, c| ...)` / `node.map_children(ast, f)`: a copy of the node
  with every child id mapped, in source order; lists that change are copied with `add_list`,
  unchanged ones kept. `f` gets `&mut Ast`, so it can allocate (deep clones in the transform).
  The result is not added to the arena.
- Traversal:
  - `walk(ast, root, &mut impl Visitor)`: an explicit stack, `enter`/`leave`, `Walk::SkipChildren` and `Stop`.
  - `ast.for_each_child`, `ast.children`.
  - `ParentMap::build(ast)` gives `parent` and `ancestors`.
- Comments: `ast.comments` sorted by position, plus `comments_in(span)` and
  `comments_between(a, b)` for printers.
- Synthesized comments: `ast.add_synthetic_comment(node, "/* E.A */", trailing)` attaches
  comment text to a node for codegen (`ast.synthetic_comments`, sorted by node id;
  `synthetic_comments_of(id)`). Transforms add them; the parser never does, so they are not
  part of `checkpoint`/`rollback`.
- Debugging: `ast.dump()` / `dump_with_source(src)`. The format is `Kind start..end field=value` with
  indented `field:` / `field[i]:` children; it is what the parser snapshot files contain.
- JSDoc (JavaScript files): `ts_r_parser::attach_jsdoc` appends the nodes it builds from JSDoc
  comments after the parsed tree. `ast.jsdoc_start` is the first of them (`u32::MAX` when there
  are none) and `ast.is_jsdoc(id)` tests one. `ast.jsdoc_tags` (sorted by host node,
  `jsdoc_tags_of(host)`) records each applied tag (`JsDocTag { host, kind, ty, span }`); a
  tag type that fills no field of the tree (`@type` on a function or an assignment target) is
  parented to its host by `ParentMap::build`. `@private`/`@protected` are recorded
  (`JsDocTagKind::Private`/`Protected`) only on assignment statements (`this.x = v`); class
  members take them as modifiers. Parsed nodes are only rewritten through
  `jsdoc_node_mut`, which logs their original values (`jsdoc_undo`); `strip_jsdoc()` restores
  the tree as parsed (same node ids), for emit and lint. `jsdoc_namespaces` lists the roots
  of dotted `@typedef`/`@callback` names (not modelled).
- `jsdoc_syntax` lists JSDoc type syntax the parser accepted in TypeScript source types
  (`JsDocSyntax { span, kind, ty }`: `?T`, `T?`, `!T`, `T!`, `*`) for the checker to report.
- `SourceKind::from_path` maps `.ts/.tsx/.mts/.cts/.d.ts/.d.mts/.d.cts/.js/.jsx/.mjs/.cjs`.

## Invariants

- `NodeId` is a non-zero `u32`; slot 0 is `Node::Dummy`. Children are allocated before their
  parents, so every child id is less than its parent's, and the root is the last node.
- `for_each_child` visits children in source order; their spans start in non-decreasing
  order.
- Spans cover their children. The one exception is zero-width `Missing` nodes from error
  recovery, which sit at the end of the previous token (see the design doc).
- JSDoc nodes break "children before parents" only where `attach_jsdoc` sets a field of an
  existing node to a JSDoc node (a parameter's `type_ann`, a function's `return_type`, a
  rebuilt statement list): their ids are larger than the parent's. Code that relies on child
  ids being smaller must not run on a JSDoc-desugared tree.
- No per-node heap allocation. Strings are `Atom`s, lists are `NodeList` ranges, flags are
  bitsets (`Modifiers` `u16`, `FnFlags` `u8`) and numbers are `F64Bits`.
- `size_of::<Node>() == 24` is asserted. Keep variants small: put extra data in lists or
  side tables rather than widening `Node`.
- Interning is per file and deterministic: the same input gives the same atom ids.
- Representation choices that consumers must know:
  - TypeScript-style optional chains: an `optional` flag on `Member`/`Index`/`Call`, with no chain
    wrapper node.
  - Assignment targets stay expressions; binding patterns appear only in declarations and
    parameters.
  - `as const` is `As` with `KeywordType Const`.
  - Literal types are the literal nodes themselves.
  - Template `parts` alternate `TemplateElement` and expression/type.
  - Parenthesised expressions and types are kept as `Paren` / `ParenType`.
  - `import<T>(x)` (an error) keeps its `TypeArgs` in `ImportCall::type_args`, so the checker
    resolves the names in them; the transform erases them.

## Testing

`cargo test -p ts_r_ast`: interner, list building, checkpoint/rollback, walk order, parent
map and the dump format. Most coverage comes from `ts_r_parser`'s unit and snapshot tests.

## Dependencies

- `ts_r_span`: `Span` (re-exported).

## Gaps

- No serialization yet (`docs/design/0001-ast.md` lists the requirements). The binder and checker
  will add side tables keyed by `NodeId`, not fields on `Node`.
- `dump` indents by depth, so it is quadratic on pathologically deep trees (only a concern
  for tests on generated input).
- JSX text is stored as a raw span; HTML entity decoding (`&amp;`) is left to codegen.
