## What it means

The postfix `e!` is an unchecked claim that a value isn't `null` or `undefined`, so it isn't allowed in sound files, whatever the type of `e`. A `!` on a value that is already non-nullable is reported too: it's harmless today but becomes a lie after a refactor. Definite assignment (`x!: T`) is a different rule ([TSR0801](TSR0801.md)).

## Example

```ts spec
// Asserting an index is in range.
const names: string[] = ["a"];
export const first: string = names[0]!.trim(); // @expect TSR0301
```

## How to fix

- Narrow with a check: `const el = document.getElementById("app"); if (el) { ... }`.
- Use `expect(value, "why it is set")` from `@ts-r.dev/guard`, which returns the non-null value and throws at runtime if it's missing.
- Delete the `!` when the operand is already non-nullable.

Sound mode is defined in [design record 0007](../../../docs/design/0007-sound-mode.md) (accepted 2026-10-15).
