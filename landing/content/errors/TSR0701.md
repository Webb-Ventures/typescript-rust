## What it means

A user-defined type predicate on a function with a body in a sound file must be proved by its body: wherever it returns true, the checker's flow type of the parameter must be assignable to the predicate type. It's reported at the predicate in the signature. Predicates without a body (interfaces, overloads, `.d.ts`) are trusted.

## Example

```ts spec
// A generic guard that always says yes.
function isPresent<T>(x: T | null): x is T { // @expect TSR0701
  return true;
}
function orEmpty(v: string | null): string {
  return isPresent(v) ? v : "";
}
export const s: string = orEmpty(null);
```

## How to fix

- Check enough in the body that the true side really is `T` (`typeof`, `instanceof`, discriminants).
- Generate the guard from the type: `return is<T>(x)` with `@ts-r.dev/guard`.
- For a guard that checks a few fields of a larger type, validate the whole type instead.

Sound mode is defined in [design record 0007](../../../docs/design/0007-sound-mode.md) (accepted 2026-10-15).
